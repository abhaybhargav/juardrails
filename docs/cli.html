CLI guide

The juard CLI lets an authorized service account discover, author, explain, evaluate, and administer policies without handling a human session token.

Service credential

Every protected command reads ~/.juardrails/credentials.json, verifies the token with /auth/me, and requires a service-account token. The file must be regular and private, and its containing directory must be private. HTTP is accepted only for loopback server URLs; use HTTPS remotely.

~/.juardrails/                 # mode 0700
└── credentials.json          # mode 0600

{"url":"https://juardrails.example.com","token":"jrd_..."}

juardrails bootstrap creates a local CLI credential on first setup. For other machines, an administrator can issue a narrower service token and inject the file there. The CLI ignores JUARDRAILS_TOKEN; do not put a human session in the file.

Policy commands

CommandPurpose
juard listList policies visible in the selected namespace
juard get ID / export IDPrint normalized YAML
juard explain IDSummarize criteria and pass conditions
juard validate FILEValidate a YAML or JSON policy
juard apply FILECreate or update a policy
juard delete IDDelete the current version
juard revisions IDInspect immutable revisions
juard evaluate ID FILERun live Jev evaluation of an active policy
juard simulate ID FILEEvaluate supplied answers without Jev
juard history [ID]Read recent evaluation traces

Use - as FILE to read JSON or YAML from stdin. Select a namespace before the command:

juard -namespace engineering/production list
juard -namespace engineering/production evaluate tool-use state.json

Administrator commands

The CLI can administer only when its service account has an explicit global admin:manage grant. The bootstrap CLI account has that grant; ordinary service accounts do not.

juard admin users list
juard admin users get ID
juard admin users create user.json
juard admin users update ID changes.json
juard admin users delete ID
juard admin users password ID password.json
juard admin users get-bindings ID
juard admin users bindings ID bindings.json

juard admin access list
juard admin access get NAME
juard admin access create grants.yaml
juard admin access update grants.yaml NAME
juard admin access delete NAME
juard admin access revisions NAME

juard admin tokens list
juard admin tokens create token.json
juard admin tokens revoke ID
juard admin namespaces list
juard admin namespaces create namespace.json
juard admin namespaces update namespace.json
juard admin auth-settings get
juard admin auth-settings set settings.json

Admin user, token, namespace, and settings files are JSON; access-policy files may be YAML or JSON. juard request METHOD /path [FILE|-] exposes advanced /api/v1 endpoints through the same service credential.

Use decisions in scripts

Never equate exit code 0 with an allow. A successful request can return block, review, or error. Parse the JSON decision and handle all other outcomes conservatively.

juard evaluate tool-use state.json | jq -e '.decision == "allow"'
Protect local inputs too

The service does not store raw evaluation state, but live evaluation sends it to the configured Jev provider. Avoid putting secrets in state unless that data flow is permitted for your deployment.
