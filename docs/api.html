REST API

The API is the shared surface for the browser, CLI, and applications. All application routes use /api/v1; only process health and password login are unauthenticated.

Request basics

Use Authorization: Bearer TOKEN for service and REST clients. The optional X-Juardrails-Namespace header defaults to root. Policy writes accept YAML or JSON; other bodies require JSON. Request bodies are limited to 1 MiB and reject unknown fields.

curl http://127.0.0.1:8080/api/v1/policies \
  -H "Authorization: Bearer $SERVICE_TOKEN" \
  -H 'X-Juardrails-Namespace: root'

Get the exact machine-readable contract from the running server at /api/v1/openapi.json, or inspect it in the repository ↗.

Policy endpoints

MethodPathPurpose
GET / POST/policiesList / create
GET / PUT / DELETE/policies/{id}Read / update / delete
POST/policies/validateValidate a policy document
GET/policies/{id}/revisionsImmutable revisions
POST/policies/{id}/evaluateLive evaluation
POST/policies/{id}/simulateSupplied-answer simulation
GET/evaluations, /evaluations/{id}History and full trace

For YAML output, set Accept: application/yaml or ?format=yaml. A PUT must include the current version; DELETE requires ?version=N. A stale version returns 409. Restore an old revision by PUTting its content with the current version to create a new revision.

Evaluation contract

POST /api/v1/policies/{id}/evaluate
Content-Type: application/json

{"state":{"message":"Please summarize this note."}}

Simulations add an answers map with a typed answer for every criterion. Live evaluation accepts only state and requires an active policy and configured provider. A response includes decision, score, per-criterion results, source, policy version, model, timing, and any error. Use only allow to authorize your action.

Identity and administration

MethodPathPurpose
POST/auth/loginPassword login for humans
GET/auth/mePrincipal, token kind, expiry, CSRF token
POST/auth/logout, /auth/passwordRevoke session / change password
GET / POST / PUT/namespacesDiscover / create / update namespaces
GET / POST/admin/principalsList / create identities
GET / PUT / DELETE/admin/principals/{id}Read / update / delete a non-admin identity
GET / PUT/admin/principals/{id}/bindingsRead / replace grants
GET / POST / PUT / DELETE/admin/access-policies and /{name}Manage access policies
GET / POST / DELETE/admin/tokens and /{id}Issue / list / revoke tokens
GET / PUT/admin/auth-settingsInspect / update supported auth settings

Admin routes require the human super-admin or a service account with explicit global admin:manage. Browser cookie writes also require X-CSRF-Token. The full OpenAPI document includes exact schemas and responses.

Failure handling

Handle 401 authentication failures, 403 denied actions, 404 missing resources or namespaces, 409 version conflicts, 422 validation failures, 429 capacity or rate limits, and 503 audit/provider availability separately. When an audit completion write fails after a mutation, the API may return 503 even if the operation committed: inspect state before retrying.
