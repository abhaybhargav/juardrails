Essentials · Browser walkthrough

Use the Web UI

The single juardrails executable serves the Web UI, API, and CLI. In the browser, you can create a policy, test its decision logic, run a live Jev evaluation, inspect the trace, and manage access.

Start here

Install the release binary, run juardrails bootstrap, then start juardrails. Open http://127.0.0.1:8080 and sign in as admin with the generated password in data/bootstrap-admin.json. If you set JUARDRAILS_ADMIN_USER and JUARDRAILS_ADMIN_PASSWORD before bootstrap, use those instead. Change the initial password under Your account and remove the bootstrap file.

The screenshots below come from an isolated demo workspace. They show actual screens and results, including a supplied-answer simulation and one live provider request. The example policy and input are illustrative.

1. Find or create a policy

Open Policies. The library shows each policy's status, question types, decision mode, and revision. Search or filter by status, then choose Create policy or open an existing row. The namespace selector in the sidebar controls which policies you see.

2. Define typed questions and pass rules

In Visual builder, enter a stable policy ID, name, description, status, and model. Add one focused criterion per question. Choose Noul for a yes/no probability, Choice for named outcomes, or Score for an ordered rubric. Set the pass condition and choose whether all, any, or a weighted fraction must pass.

Use Validate before Save policy. The YAML policy tab lets you edit or import the same definition as code, and Export downloads it. Saving an existing policy creates a new revision.

3. Simulate before using a provider

Open Playground, select a draft or active policy, and keep Simulation · supplied answers selected. Enter representative state and edit the generated typed-answer fixture to test passing, failing, and borderline cases. Choose Run simulation to see the decision and each criterion's result. Simulation checks the decision rules against your answers; it does not ask Jev to judge the state.

4. Evaluate an active policy with Jev

Change the policy status to Active — live evaluation enabled and save it. Configure a Jev provider key on the server, then select Live · Jev API in Playground. Enter text or structured JSON and choose Evaluate with Jev. The server sends the state to the configured provider and combines the typed answers under the saved pass rules. Review the decision, policy revision, criterion outcomes, model, and duration before connecting it to an enforcing application.

Enforce in your caller

Juardrails returns a decision. Your application or agent hook must proceed only on allow and handle block, review, error, and request failures.

5. Inspect the decision record

Open Evaluations to filter recent runs by policy. The table separates simulation from Jev results and shows revision, outcome, pass score, and duration. Choose Inspect for the saved criterion trace. Juardrails does not store the raw input state in evaluation history.

6. Scope access as an administrator

The human super-admin can open Access control to create namespaces, people, and service accounts; define namespace-action grants; bind policies; and issue expiring service tokens. New accounts have no grants until a policy is bound. For CLI use, install the same binary on the client machine and inject a service token into ~/.juardrails/credentials.json; browser passwords and sessions do not authenticate the CLI.

Continue with the policy model, access control, or CLI guide for exact fields and commands.
