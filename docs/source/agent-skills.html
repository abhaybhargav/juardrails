Give an agent a policy it can use

Generate a small, policy-specific skill from an active Juardrails policy. The skill tells another agent when to consult the policy and how to evaluate it through its own authorized service account.

1. Add an AI provider key

In the Web UI, open an active policy and choose Agent skill. Enter an OpenAI-compatible API key for this generation, or configure SKILL_AI_API_KEY in the server environment or its .env file. The browser field is used once and cleared after submission. The key is not persisted in Juardrails or included in the downloaded skill.

SKILL_AI_API_KEY=your-provider-key
SKILL_AI_MODEL=gpt-4.1-mini
# Optional for a compatible provider you operate or trust:
# SKILL_AI_ENDPOINT=https://provider.example/v1/chat/completions

The default endpoint is https://api.openai.com/v1/chat/completions. A custom endpoint can be set by the server operator and must use HTTPS, except for loopback development endpoints. The harness sends the policy definition to that provider and uses its answer only for short discovery wording; Juardrails writes the evaluation steps. This generation call is separate from the Jev provider used for policy decisions. See the OpenAI Chat Completions API for the default provider contract.

2. Generate and inspect the skill

Choose Generate and download skill ZIP. The policy must be saved and active, and your account must have policies:read in its namespace. The ZIP contains SKILL.md and references/policy.yaml inside a named skill directory. The snapshot records the policy revision at generation time; the skill tells the agent to inspect the current policy before it evaluates.

Review the generated wording and policy snapshot before installation. A change to the policy may make the skill’s discovery text stale; regenerate it after a meaningful revision.

3. Install in an agent

Extract the ZIP into the skill directory used by your agent or harness. For example, Claude Code can load it from ~/.claude/skills/ or a project’s .claude/skills/; Codex can load it from ~/.codex/skills/. The ZIP already contains the skill folder, so extract it at the parent directory.

unzip juardrails-root-support-safety.zip -d ~/.claude/skills/
# Or for Codex:
unzip juardrails-root-support-safety.zip -d ~/.codex/skills/

Install the Juardrails executable on the agent machine and inject a service-account credential at ~/.juardrails/credentials.json. Grant that account policies:read and policies:evaluate for the policy namespace. The generated skill never carries a credential and does not bypass server grants.

Generate from the CLI

An authorized service account can request the same bundle from a terminal. Set SKILL_AI_API_KEY in that process if the server has no configured key. The output file must not already exist.

juardrails cli -namespace root skill support-safety support-safety-skill.zip

The API endpoint is POST /api/v1/policies/{id}/skill with JSON fields api_key and model, both optional when server defaults are configured. It returns application/zip. Cookie-authenticated browser requests require the usual CSRF token.

4. Let the agent evaluate

The skill directs the agent to inspect the current policy, prepare a JSON state file, and run juardrails cli -namespace NAME evaluate ID STATE_FILE. It treats only an explicit allow decision as permission to proceed. Draft policies cannot produce a skill because they cannot run live evaluations.

A skill is guidance, not a hook

Skill installation does not intercept every tool call or enforce a decision by itself. For automatic pre-action enforcement, pair the policy with a harness hook such as the Claude Code pack. Live evaluation sends the chosen state to your configured Jev provider; include only data that deployment is allowed to send.
