Stop unsafe Pods at admission

The Kubernetes security pack runs a Juardrails policy inside a TLS validating webhook. A Pod is admitted only when both the live Jev evaluation says allow and fixed security checks pass.

Seven of seven API-server dry runs matched their expected results. A normal create admitted the safe Pod; a normal create rejected a hostPath Pod. This is a small demonstration, not a detection or latency benchmark.

Controls inspired by Kyverno

The pack draws on Kyverno's non-root policy, strict capability policy, and the Kubernetes Pod Security Standards. Its baseline checks privileged mode, privilege escalation, root execution, Linux capabilities, seccomp, host access, service-account token automount, and floating image tags. The Jev policy classifies isolation, identity exposure, and image tag hygiene from a normalized Pod security view. It does not inspect commands, environment values, annotations, or Secret contents.

Deploy the demonstration

Use Docker, kubectl, Go, Python 3, OpenSSL, and a TYPESAFE_API_KEY in the repository .env or environment. The installer requires an explicit kube context, creates a local container image, provisions a one-replica Juardrails server with SQLite storage, and injects a limited evaluator credential at ~/.juardrails/credentials.json in the webhook container.

go install sigs.k8s.io/kind@v0.30.0
"$(go env GOPATH)/bin/kind" create cluster --name juardrails-admission
python3 policy_packs/kubernetes-security/install.py \
  --context kind-juardrails-admission --kind-cluster juardrails-admission
python3 policy_packs/kubernetes-security/smoke.py \
  --context kind-juardrails-admission --output /tmp/juardrails-kubernetes-smoke.json

The pack README and manifests explain an existing-cluster deployment and removal. Only namespaces labeled juardrails.io/admission=enabled are matched. The webhook uses failurePolicy: Fail, a 20-second timeout, and a CA bundle for the service certificate, following the Kubernetes AdmissionReview contract.

Enforcement boundary

The Juardrails provider key stays in a Kubernetes Secret read by the server. The webhook receives a different service token with only policies:evaluate in kubernetes-security; the installer checks that it cannot read root. The webhook denies block, review, error, and any CLI or provider failure. Baseline failures remain denied even if Jev reports allow. The provider receives image references and security settings; make sure that data flow fits your environment.

This demo uses one Pod and SQLite, and its self-generated TLS certificate and evaluator token require rotation. For production, plan high availability, backups, certificate management, calibrated policy thresholds, and RBAC that protects namespace labels and webhook configuration. Pod Security Admission or Kyverno can remain in place as independent controls.
