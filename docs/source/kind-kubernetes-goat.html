Cookbooks · Kind + Kubernetes Goat

Prove admission blocks a vulnerable workload

Run Juardrails on a disposable Kind cluster, feed it the real Kubernetes Goat system-monitor Pod template, and inspect the API-server denial and ReplicaSet event.

Observed on 4 October 2026

The Goat Pod dry run was denied by the Juardrails webhook. Its temporary Deployment was created, but the ReplicaSet's Pod create was denied with a FailedCreate event. No vulnerable Pod started. A separate seven-case control suite matched 7/7 expected decisions.

What this test deploys

The source is Kubernetes Goat's pinned system-monitor manifest. Its Pod template asks for host PID and IPC, a hostPath mount of /, and privileged mode. The probe reads that Deployment template and creates only a dedicated goat-guarded namespace and temporary workload. It does not run Goat's setup script, install its cluster-wide RBAC examples, or start the vulnerable container. Kubernetes Goat is an intentionally vulnerable training project.

1. Start Kind

From the Juardrails repository root, have Docker, Go, kubectl, Python 3, OpenSSL, and TYPESAFE_API_KEY in this repository's .env or environment.

go install sigs.k8s.io/kind@v0.30.0
"$(go env GOPATH)/bin/kind" create cluster --name juardrails-goat --wait 120s
kubectl --context kind-juardrails-goat get nodes

2. Install the admission pack

python3 policy_packs/kubernetes-security/install.py \
  --context kind-juardrails-goat --kind-cluster juardrails-goat
kubectl --context kind-juardrails-goat -n juardrails-system \
  rollout status deployment/juardrails-admission --timeout=180s

The installer creates Juardrails and a TLS validating webhook. The webhook uses a service token with only policies:evaluate in kubernetes-security, stored at ~/.juardrails/credentials.json inside the webhook container. Only namespaces labeled juardrails.io/admission=enabled are matched. See the pack architecture and controls.

3. Fetch the tested Goat revision

Pinning the source commit ensures an upstream manifest change cannot silently alter the scenario.

mkdir -p /tmp/juardrails-kubernetes-goat
git -C /tmp/juardrails-kubernetes-goat init
git -C /tmp/juardrails-kubernetes-goat fetch --depth 1 \
  https://github.com/madhuakula/kubernetes-goat.git \
  723a0db478f050d173d23b4ce5044b65bce0bdd0
git -C /tmp/juardrails-kubernetes-goat checkout --detach FETCH_HEAD

4. Run the Goat probe

python3 policy_packs/kubernetes-security/goat_probe.py \
  --context kind-juardrails-goat \
  --goat-dir /tmp/juardrails-kubernetes-goat \
  --output /tmp/juardrails-goat-observed.json

Expected output:

Goat Pod dry-run: denied by Juardrails webhook
Goat Deployment: created; child Pod denied with FailedCreate event; no Pod exists

The direct Pod request is a server-side dry run. The Deployment creation is real but temporary. Since the validating webhook targets Pods, Kubernetes can accept the Deployment object; its ReplicaSet then receives the denial when it tries to create a Pod. The probe verifies the event, checks there is no Pod, and deletes the Deployment.

5. Inspect the evidence and run controls

kubectl --context kind-juardrails-goat -n goat-guarded get pods
kubectl --context kind-juardrails-goat -n goat-guarded get events \
  --field-selector reason=FailedCreate --sort-by=.lastTimestamp
kubectl --context kind-juardrails-goat -n juardrails-system \
  exec deployment/juardrails-admission -c server -- \
  juardrails cli -namespace kubernetes-security history kubernetes-pod-security
python3 policy_packs/kubernetes-security/smoke.py \
  --context kind-juardrails-goat \
  --output /tmp/juardrails-goat-smoke.json

The event should identify pod-security.juardrails.io and the blocked host and privilege settings. Juardrails history shows Jev's answers and timing; controller retries may produce multiple records. The control suite admits one hardened Pod and denies six unsafe variants. It exits nonzero on a mismatch. The sanitized Goat observation records the tested outcome.

Clean up

"$(go env GOPATH)/bin/kind" delete cluster --name juardrails-goat

Deleting the lab cluster removes its provider Secret, evaluator token, database, and audit history. If the probe fails, check the webhook Pod's readiness and logs, the namespace label, the webhook CA bundle, and the FailedCreate events. A provider outage fails closed for labeled namespaces. This pack checks Pod admission; it does not prevent Goat's separate RBAC, SSRF, or application-level exercises. The repository guide includes the same commands and operational limits.
