Build · Command line

CLI guide

The juardrails cli command lets an authorized service account discover, author, explain, evaluate, and administer policies without handling a human session token.

Install the single Juardrails executable for macOS, Linux, or Windows. Run protected commands as juardrails cli …; the same file also starts the server and bootstraps the first identities.

Service credential

Every protected command reads ~/.juardrails/credentials.json, verifies the token with /auth/me, and requires a service-account token. The file must be regular and private, and its containing directory must be private. HTTP is accepted only for loopback server URLs; use HTTPS remotely.

~/.juardrails/                 # mode 0700
└── credentials.json          # mode 0600

{"url":"https://juardrails.example.com","token":"jrd_..."}

juardrails bootstrap creates a local CLI credential on first setup. For other machines, an administrator can issue a narrower service token and inject the file there. The CLI ignores JUARDRAILS_TOKEN; do not put a human session in the file. On Windows, mode bits do not describe access; the CLI checks the directory and file ACLs instead. Allow only your user, SYSTEM, and Administrators.

Policy commands

CommandPurpose
juardrails cli listList policies visible in the selected namespace
juardrails cli get ID / export IDPrint normalized YAML
juardrails cli explain IDSummarize criteria and pass conditions
juardrails cli validate FILEValidate a YAML or JSON policy
juardrails cli apply FILECreate or update a policy
juardrails cli delete IDDelete the current version
juardrails cli revisions IDInspect immutable revisions
juardrails cli evaluate ID FILERun live Jev evaluation of an active policy
juardrails cli simulate ID FILEEvaluate supplied answers without Jev
juardrails cli history [ID]Read recent evaluation traces

Use - as FILE to read JSON or YAML from stdin. Select a namespace before the command:

juardrails cli -namespace engineering/production list
juardrails cli -namespace engineering/production evaluate tool-use state.json

Administrator commands

The CLI can administer only when its service account has an explicit global admin:manage grant. The bootstrap CLI account has that grant; ordinary service accounts do not.

juardrails cli admin users list
juardrails cli admin users get ID
juardrails cli admin users create user.json
juardrails cli admin users update ID changes.json
juardrails cli admin users delete ID
juardrails cli admin users password ID password.json
juardrails cli admin users get-bindings ID
juardrails cli admin users bindings ID bindings.json

juardrails cli admin access list
juardrails cli admin access get NAME
juardrails cli admin access create grants.yaml
juardrails cli admin access update grants.yaml NAME
juardrails cli admin access delete NAME
juardrails cli admin access revisions NAME

juardrails cli admin tokens list
juardrails cli admin tokens create token.json
juardrails cli admin tokens revoke ID
juardrails cli admin namespaces list
juardrails cli admin namespaces create namespace.json
juardrails cli admin namespaces update namespace.json
juardrails cli admin auth-settings get
juardrails cli admin auth-settings set settings.json

Admin user, token, namespace, and settings files are JSON; access-policy files may be YAML or JSON. juardrails cli request METHOD /path [FILE|-] exposes advanced /api/v1 endpoints through the same service credential.

Use decisions in scripts

Never equate exit code 0 with an allow. A successful request can return block, review, or error. Parse the JSON decision and handle all other outcomes conservatively.

juardrails cli evaluate tool-use state.json | jq -e '.decision == "allow"'
Protect local inputs too

The service does not store raw evaluation state, but live evaluation sends it to the configured Jev provider. Avoid putting secrets in state unless that data flow is permitted for your deployment.
