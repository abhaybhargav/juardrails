Essentials · 5 minutes

Get started

Run the service, create a local CLI credential, and evaluate a policy. The CLI authenticates as a service account from a private file on your machine.

Requirements

Go 1.26+ and a local checkout of the repository. Live evaluation needs a configured TypeSafe Jev key or another supported Jev provider; simulation does not.

Bootstrap the server

Build both binaries

From the repository root, run make build. This produces bin/juardrails and bin/juard.

Create the initial identities

Run ./bin/juardrails bootstrap. It creates the permanent human super-admin and a dedicated cli-admin service account.

Start the server

Run ./bin/juardrails and open http://127.0.0.1:8080. Keep it running while using the CLI.

make build
./bin/juardrails bootstrap
./bin/juardrails

The generated human admin password is stored at data/bootstrap-admin.json with mode 0600. Sign in, change the password under Your account, then remove that bootstrap file. The CLI credential is stored separately at ~/.juardrails/credentials.json in a private directory. Bootstrap refuses to overwrite it.

Load and inspect a policy

The included support-safety policy is a draft, so you can inspect and simulate it immediately. The example simulation supplies Jev answers explicitly and does not call a provider.

./bin/juard apply examples/support-safety.yaml
./bin/juard list
./bin/juard explain support-safety
./bin/juard simulate support-safety examples/simulation.json

To change the policy, edit its YAML, run juard validate FILE, then juard apply FILE. On update, the CLI uses the current server version unless the file supplies an explicit version. Every save creates a revision.

Enable live evaluation

Put TYPESAFE_API_KEY in the server's .env file or environment and restart the server. Set the policy status to active. Then pass a JSON state file to evaluate:

# examples/state.json contains {"state": ...}
./bin/juard evaluate support-safety examples/state.json
Decisions are not enforcement

Only decision: "allow" is an allow. Your application must handle block, review, error, failed requests, and transport errors before acting.
