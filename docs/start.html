Essentials · 5 minutes

Get started

Install one executable, bootstrap the first identities, and create a guardrail in the browser. The same juardrails file serves the Web UI and API and runs the service-account CLI.

Requirements

Install the single release binary for your OS, or build from source with Go 1.26+. Live evaluation needs a configured TypeSafe Jev key or another supported Jev provider; simulation does not.

Bootstrap the server

Install the executable

Use the release installer for macOS, Linux, or Windows. Add its install directory to PATH if needed.

Create the initial identities

Run juardrails bootstrap. It creates the permanent human super-admin and a dedicated cli-admin service account.

Start the server

Run juardrails and open http://127.0.0.1:8080. Keep it running while using the browser or CLI.

juardrails version
juardrails bootstrap
juardrails

The generated human admin password is stored at data/bootstrap-admin.json with private permissions. Sign in as admin, change the password under Your account, then remove that bootstrap file. The CLI credential is stored separately at ~/.juardrails/credentials.json in a private directory. Bootstrap refuses to overwrite it.

Create and test in the Web UI

Open Policies → Create policy. Add typed questions and thresholds in the visual builder, choose Validate, then Save policy. Open Playground to simulate supplied answers while the policy is a draft. The illustrated Web UI walkthrough shows every step, including live Jev evaluation, history, and access control.

Optional: load the example with the CLI

The included support-safety policy is a draft, so you can inspect and simulate it immediately. The CLI uses the local service-account credential created by bootstrap. The example simulation supplies Jev answers explicitly and does not call a provider.

curl -fL https://raw.githubusercontent.com/abhaybhargav/juardrails/main/examples/support-safety.yaml -o support-safety.yaml
curl -fL https://raw.githubusercontent.com/abhaybhargav/juardrails/main/examples/simulation.json -o simulation.json
juardrails cli apply support-safety.yaml
juardrails cli list
juardrails cli explain support-safety
juardrails cli simulate support-safety simulation.json

The example files are in the repository; on Windows, download them from the examples directory or supply your own policy and state files. To change a policy, edit its YAML, run juardrails cli validate FILE, then juardrails cli apply FILE. On update, the CLI uses the current server version unless the file supplies an explicit version. Every save creates a revision.

Enable live evaluation

Put TYPESAFE_API_KEY in the server's .env file or environment and restart the server. Set the policy status to active. Then pass a JSON state file to evaluate:

curl -fL https://raw.githubusercontent.com/abhaybhargav/juardrails/main/examples/state.json -o state.json
juardrails cli evaluate support-safety state.json
Decisions are not enforcement

Only decision: "allow" is an allow. Your application must handle block, review, error, failed requests, and transport errors before acting.
