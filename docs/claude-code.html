Integrations · Policy pack

Secure Claude Code tool calls

The Claude Code pack combines one active Juardrails policy, a project-scoped PreToolUse hook, and two agent skills. The hook screens a proposed action before Claude Code runs it.

Claude proposes a tool callBash, Edit, MCP, and other matched tools
→
Hook calls juardrails cli evaluateService account from the local credential file
→
Policy returns a decisionOnly allow passes to normal permissions

What the policy checks

The claude-code-tool-use policy uses three Noul risk questions in all mode. A tool call must pass all three.

CriterionDefault maximum riskExamples
Destructive change0.20Recursive deletion, overwriting substantial data, disabling controls
Secret exposure0.40Posting credentials or sensitive data to another destination
Unsafe external action0.20Publishing, deployment, remote changes, executing untrusted code

The hook also rejects obvious credential references locally before sending a call to the provider. This catches common token patterns and secret paths; it is not a complete secret scanner. The policy is a starting point, so calibrate it with examples from your own workflows.

The three questions share one Jev provider request. This makes the pack a practical example of guarding several risks without chaining three model calls. Read why Jev for published performance evidence; actual hook latency includes CLI, server, network, and provider time.

Install the pack

Prepare Juardrails

Install the release binary and start a server with a Jev provider. Provision a service credential with policy read, create, update, and evaluate actions in the intended namespace.

Get the pack files

Clone or download the repository to obtain the policy, hook, skills, and Python installer. The release binary itself has no Go or Node dependency.

Install into one project

Run the installer below. It applies the policy, copies the hook and skills, and merges project .claude/settings.json without discarding existing settings.

python3 policy_packs/claude-code/install.py /path/to/claude-project \
  --juard "$(command -v juardrails)"

# Optional: install in a namespace other than root
python3 policy_packs/claude-code/install.py /path/to/claude-project \
  --juard "$(command -v juardrails)" --namespace engineering/production

The example uses macOS/Linux shell syntax. The installer also accepts the legacy juard binary. The Windows release supports juardrails.exe cli; this project hook installer has been tested on macOS/Linux. Use --no-apply for an offline file install, then apply the YAML policy yourself. Use --force to replace differing pack files. Keep the executable at the --juard path for the installed hook; put it on Claude Code's PATH so skills can run juardrails cli interactively.

The included skills

/juardrails

Guides an agent to discover, explain, validate, apply, simulate, and evaluate authorized policies with the CLI.

/claude-code-guardrails

Explains this integration, its policy, and how to inspect decision history without bypassing a denial.

The installer places both in the project’s .claude/skills/ directory. For another harness, copy the general Juardrails skill ↗ to that harness’s skill directory. For Codex, the conventional location is ~/.codex/skills/juardrails/. A skill provides guidance; enforcement requires a harness hook or equivalent tool interception.

Coverage and behavior

The hook matches Bash, PowerShell, Write, Edit, MultiEdit, NotebookEdit, WebFetch, WebSearch, and MCP tool calls. It sends the proposed input to the active policy through the service-account-backed CLI. It denies block, review, error, malformed responses, oversized input, or service failure. An allow leaves Claude Code’s normal permission rules in place.

juardrails cli explain claude-code-tool-use
juardrails cli history claude-code-tool-use
Understand the data flow and boundary

Live evaluation sends proposed tool input, potentially including file content, to the configured Jev provider. The local credential check is best effort. Other tool types and actions outside Claude Code are not screened. Project hooks can be edited or disabled, and Claude Code may proceed if a hook process is killed or times out. Use managed settings and operating-system controls where a stronger enforcement boundary is required.

Test before rollout

Try representative safe and risky calls in a disposable project. A routine listing or go test ./... should pass; recursive deletion or a command posting .env to a remote URL should not. Review the returned criterion scores and tune the policy before applying it broadly.

python3 -m unittest discover -s policy_packs/claude-code/tests -v
go test ./...
juardrails cli history claude-code-tool-use
