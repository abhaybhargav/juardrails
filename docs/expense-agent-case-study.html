Case study · Agent integration

An expense agent that cannot approve past its policy

We built a small OpenAI expense agent, generated a policy-specific Juardrails skill with a real OpenAI API call, and ran fictional reimbursement requests through a live TypeSafe Jev policy gate. The agent could propose an action; the harness allowed simulated approval only after an explicit allow.

Observed on 27 September 2026

Six of six live cases matched their expected guardrail decisions. Four additional supplied-answer cases exercised allow, block, review, and error. A missing CLI executable also produced an error and prevented approval. This is one small scenario suite, not a general accuracy benchmark or a production expense system.

What we built

The agent reviews travel, client meals, and work software expenses. Its active policy, expense-demo/expense-approval, requires all four criteria to pass. The local agent has a service account with only policies:read, policies:evaluate, and policies:simulate in that namespace. The reproducer confirms the account is denied administrator commands and reads in root. Its service token lives in a private ~/.juardrails/credentials.json under the isolated test home.

CriterionPass rule
Delegated limitUSD amount is at most $500
DocumentationItemized receipt reference and concrete business purpose are present
CategoryBusiness travel, client meal, or work software; gift cards and personal purchases fail
Rule overrideProbability of an instruction to bypass approval rules is at most 0.2

We used OPENAI_API_KEY to generate the installed skill. Its discovery text names the expense checks; Juardrails supplies the CLI and fail-closed instructions. The agent receives the skill and policy snapshot, then calls an evaluate_expense tool. The harness runs juardrails cli explain to check the current revision, then sends the canonical expense record, not a model-rewritten copy, to juardrails cli evaluate. The model receives the tool result and writes a final response, while the harness computes the effective action independently. The tool call uses the OpenAI Chat Completions API.

The agent’s final status matched the gate in all six cases: approved once and needs_human_review five times. Juardrails recorded policy revision 1 and criterion traces for each live request. Its reported Jev durations in this run ranged from 689 to 1,782 ms, with a median of 944 ms. Those timings exclude the agent’s two OpenAI calls per case and should not be treated as a latency guarantee or a comparison benchmark.

Review and failure behavior

We then supplied typed answers directly to juardrails cli simulate to exercise decision-engine branches that did not appear in the live requests. A documentation answer with confidence 0.44, below the policy minimum 0.7, returned review. Omitting required answers returned an error. Both routed to human review in the harness.

For a separate service-failure check, the agent proposed approval for the valid train ticket while the CLI executable path was deliberately invalid. The harness recorded error, routed the request to human review, and the model’s final response said approval could not be confirmed.

Reproduce the study

The case-study source includes the policy, fictional requests, saved generated skill, agent harness, supplied-answer fixtures, tests, and sanitized observations. With Go, Python 3, and valid OPENAI_API_KEY and TYPESAFE_API_KEY in the repository .env, run:

python3 examples/expense-approval/run_study.py \
  --artifacts-dir /tmp/expense-study-output

The reproducer creates an isolated server and a short-lived, restricted service account; it removes credentials and the test database on exit. The artifact directory retains only the generated skill ZIP and raw observations. Run python3 -m unittest discover -s examples/expense-approval -p 'test_*.py' for the local gate tests. Provider answers and timings may vary on a later run.

What this demonstrates

The skill helped the agent find and invoke the policy, while the harness enforced the result. A skill alone is advisory; production expense approval needs a server-side gate before any irreversible reimbursement action. Exact numeric limits and receipt existence should also be checked against authoritative finance records before paying, rather than relying solely on model interpretation of submitted text.
