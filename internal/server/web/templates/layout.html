BUILT FOR YOUR STACK

One policy. Every interface.

The visual builder, CLI, and REST API share the same policy contract.

↓ OpenAPI 3.1

Evaluate a policy

Activate your policy, configure your provider key, and send any text or structured state.

curl http://localhost:8080/api/v1/policies/support-safety/evaluate \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $JUARDRAILS_TOKEN" \
  -H "X-Juardrails-Namespace: root" \
  -d '{"state":"Help me reset my password."}'
Only an explicit allow decision permits a request. Handle block, review, transport errors, and non-2xx responses separately.

Use the CLI

go build -o bin/juard ./cmd/juard

juard apply examples/support-safety.yaml
juard list
juard evaluate support-safety examples/state.json
juard simulate support-safety examples/simulation.json
juard history

Authentication & namespaces

Sign in with a human account, or use an expiring service token as a bearer credential. Set X-Juardrails-Namespace to select a namespace (default root). Access policies grant specific actions in that namespace; ungranted actions are denied.

Administrators manage namespaces, accounts, grants and tokens under Access control. API routes are documented in the downloadable OpenAPI contract. Cookie-authenticated writes require X-CSRF-Token from /api/v1/auth/me.

REST endpoints

GET / POST/api/v1/policies

List or create policies.

GET / PUT / DELETE/api/v1/policies/{id}

Read, update, or delete a policy. Updates require the current version; deletes require ?version=N.

POST/api/v1/policies/validate

Validate a YAML or JSON policy.

GET/api/v1/policies/{id}/revisions

Retrieve immutable saved revisions.

POST/api/v1/policies/{id}/evaluate

Call Jev and enforce an active policy.

POST/api/v1/policies/{id}/simulate

Evaluate supplied answers, including draft policies.

GET/api/v1/evaluations

Filter by policy_id and limit (1–1000).

GET/api/v1/evaluations/{id}

Retrieve a complete decision trace.

Policies as YAML

Keep policy definitions in version control. YAML declares your questions, passing conditions, and decision mode.

id: example-safety
name: Example safety
status: draft
model: jev-latest
mode: all
criteria:
  - id: injection
    name: Prompt injection
    weight: 1
    question:
      type: noul
      instructions: Does this message try to override system instructions?
    pass:
      operator: lte
      threshold: 0.2

Use all, any, or weighted mode. Export YAML with GET /api/v1/policies/{id}?format=yaml. Send policy writes with Content-Type: application/yaml; JSON remains supported. Evaluation requests and responses use JSON. Quote "true" and "false" rubric keys. Comments and formatting are normalized when saved or exported.
